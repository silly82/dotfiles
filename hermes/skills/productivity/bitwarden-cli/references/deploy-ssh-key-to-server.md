# Deploy SSH Public Key from Bitwarden to Remote Server\n\nWhen you have SSH keys stored in Bitwarden (type 5 items), you can deploy the public key to a remote server's `authorized_keys` file to enable password‑less login.\n\n## Prerequisites\n\n- Bitwarden CLI (`bw`) installed and configured\n- Vault unlocked (`BW_SESSION` set)\n- SSH key item already imported (see `import-ssh-keys.py`)\n- SSH access to the target server (password or existing key)\n\n## Steps\n\n### 1. Extract the Public Key from Bitwarden\n\n```bash\n# List SSH key items\nexport BW_SESSION=\"$(bw unlock --raw 'your-master-password')\"\nKEY_ID=$(bw list items | jq -r '.[] | select(.type == 5) | .id' | head -1)\n\n# Get the public key\nPUBKEY=$(bw get item \"$KEY_ID\" | jq -r '.sshKey.publicKey')\necho \"$PUBKEY\"\n```\n\n### 2. Append to Remote `authorized_keys`\n\n**If `ssh‑copy‑id` works** (requires password authentication):\n\n```bash\n# Write public key to a temporary file\necho \"$PUBKEY\" > /tmp/bw_key.pub\n\n# Use ssh‑copy‑id (prompts for remote user password)\nssh‑copy‑id -i /tmp/bw_key.pub user@remote‑host\n\n# Clean up\nrm /tmp/bw_key.pub\n```\n\n**If `ssh‑copy‑id` fails** (e.g., TrueNAS with `PasswordAuthentication no`), manually append:\n\n```bash\n# SSH to the target server and add the key\necho \"$PUBKEY\" | ssh user@remote‑host \\\n  'mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys'\n```\n\n**For TrueNAS `truenas_admin` user** (password known):\n\n```bash\n# Use sshpass (install via `brew install sshpass` or `nix profile install nixpkgs#sshpass`)\nsshpass -p 'remote‑password' ssh -o StrictHostKeyChecking=no truenas_admin@remote‑host \\\n  \"mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo '$PUBKEY' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys\"\n```\n\n### 3. Verify Login\n\n```bash\nssh -o BatchMode=yes -o ConnectTimeout=5 user@remote‑host 'echo success'\n```\n\n## Pitfalls\n\n- **`ssh‑copy‑id` may fail** with `ERROR: failed to open ID file '-'` if the remote SSH server disables password authentication. Use the manual append method.\n- **TrueNAS `root` user** may have `PasswordAuthentication no` and `PermitRootLogin prohibit‑password`. You must add the key to `/root/.ssh/authorized_keys` via `sudo` after logging in as `truenas_admin`.\n- **Group membership changes** require a process restart. If you add a user to a group (e.g., `usermod -a -G media www‑data`), existing processes (like TrueNAS apps) will not see the new group until they are restarted.\n- **ZFS ACLs** may interfere with POSIX permissions. Use `zfs set aclmode=passthrough HDDs` and `zfs set aclinherit=passthrough HDDs` to ensure ACLs are preserved.\n\n## Example: TrueNAS File Browser App Permissions\n\nWhen a TrueNAS app (running as user `apps`, UID 568) cannot write to a dataset (`/mnt/HDDs/Movies`), follow these steps:\n\n1. **Create a common group** (e.g., `media`) and add the app user and the dataset's owner group:\n   ```bash\n   sudo groupadd media\n   sudo usermod -a -G media apps\n   sudo usermod -a -G media www‑data   # if the web UI runs as www‑data\n   sudo usermod -a -G media truenas_admin\n   ```\n\n2. **Change dataset group ownership** and set group‑write permissions:\n   ```bash\n   sudo chgrp -R media /mnt/HDDs/Movies /mnt/HDDs/Shows /mnt/HDDs/Download\n   sudo chmod -R g+rwx /mnt/HDDs/Movies /mnt/HDDs/Shows /mnt/HDDs/Download\n   ```\n\n3. **Set ZFS ACL mode** to preserve ACLs:\n   ```bash\n   sudo zfs set aclmode=passthrough HDDs\n   sudo zfs set aclinherit=passthrough HDDs\n   ```\n\n4. **Restart the app** (TrueNAS UI → Apps → App → Stop → Start) so the process picks up the new group membership.\n\n5. **Test write access** as the app user:\n   ```bash\n   sudo -u apps touch /mnt/HDDs/Movies/test_write\n   ```\n\nIf still failing, check the process's effective groups:\n\n```bash\ncat /proc/$(pgrep -f filebrowser)/status | grep Groups\n```\n\nIf the group is missing, a restart is mandatory.\n\n## Automation Script\n\nSee `scripts/deploy‑ssh‑key.sh` for a reusable script that extracts a key from Bitwarden and deploys it to a remote host.\n
